1. 프로젝트 목표

CCTV 주차장 영상을 입력으로 받아 주차면별 차량 점유 여부를 판단하고, 전체 주차 점유율을 확인하는 프로그램을 만드는 것이 목표다.
초기에는 실제 CCTV 직접 연동보다, CCTV 화면을 촬영한 영상 또는 주차장 연습 영상을 기반으로 기능을 검증한다.
최종적으로는 현장 CCTV 또는 별도 설치 카메라에서 일정 주기로 프레임을 가져와 주차면 상태를 자동 분석하는 형태가 적합하다.

2. 회의 기반 핵심 요약

2-1. 6월 12일 회의

- 주차장 프로젝트의 기본 방향은 CCTV 입력 영상에서 차량을 인식하고, 차량이 지정된 주차 구역과 겹치면 해당 주차면을 점유 상태로 판단하는 것이다.
- 기존 샘플 영상은 휴대폰으로 CCTV 모니터를 촬영한 형태라 빛 반사, 흔들림, 낮은 해상도 문제가 있었다.
- CCTV 직접 접근이 어렵기 때문에 우선 샘플 영상으로 카메라 각도, 차량 수, 해상도, 현장 제약을 파악하는 용도로 활용한다.
- 처음에는 큰 주차 구역을 기준으로 판단했으나, 한 차량이 여러 주차면에 걸쳐 잡히는 문제가 있어 주차 구역을 좁히는 방식이 필요했다.
- 화면 전체를 한 번에 YOLO에 넣으면 겹침이나 가림이 있는 차량을 놓치는 문제가 있었고, 화면을 여러 영역으로 나누어 분석하면 정확도가 개선될 수 있다.
- 주차 상태는 매 프레임 바뀌는 정보가 아니므로 실시간 전체 프레임 처리보다 10초, 30초, 1분 단위의 주기적 분석이 현실적이다.
- 움직이는 차량이나 일시적으로 가려진 주차면은 바로 점유/비점유로 단정하지 않고 unknown 상태를 두는 것이 좋다.
- CCTV 각도가 비스듬하기 때문에 단순 사각형 박스보다 회전 사각형, 사다리꼴, 투시 변환 기반의 주차면 판단이 필요하다.
- 단순 데모가 아니라 설치자가 실제 사용할 수 있는 프로그램 형태가 중요하다.

2-2. 6월 25일 회의

- 7월 말 전후로 1차 프로토타입을 제시하고, 이후 8월 말과 10월까지 완성도를 높이는 일정 흐름이 언급되었다.
- 주차장 프로젝트는 새로 고정된 카메라로 차량이 들어오고 나가는 영상을 촬영해 더 좋은 테스트 데이터를 확보하는 것이 필요하다.
- 프로그램은 알고리즘만이 아니라 사용자가 주차면을 설정하고 분석을 실행할 수 있는 GUI 또는 보조 프로그램까지 고려해야 한다.

2-3. 6월 30일 회의

- 교수님 예시 코드는 학습용이며, 반드시 동일 방식만 고집할 필요는 없다.
- 다만 고정 CCTV 환경에서는 주차면 위치가 자주 바뀌지 않으므로, 자동 주차면 검출보다 사용자가 첫 프레임에서 주차면 좌표를 지정하고 이를 저장해 재사용하는 구조가 효율적이다.
- 권장 흐름은 첫 프레임 캡처, 주차면 4점 클릭, P1/P2/P3 같은 주차면 ID 지정, JSON/CSV/TXT 저장, 분석 프로그램에서 해당 좌표 파일을 읽는 방식이다.
- VLM을 사용해 “오른쪽 첫 번째/두 번째/세 번째 주차면이 비었는가”처럼 질문하는 방식도 가능하지만, 안정성과 학습 목적을 고려하면 YOLO 기반 시각 알고리즘을 먼저 구성하고 VLM은 보조 판단으로 두는 것이 좋다.
- 흔들리는 영상, 측면 각도, 인접 차량 겹침 문제 때문에 영상 안정화, 회전/사다리꼴 주차면, 투시 변환 방식이 중요하다.

2-4. 7월 9일 회의

- 주차장 UI는 웹앱 형태로 보여졌고, 최종 사용자는 설치 후 자동 동작에 가깝게 쓰는 구조가 좋다는 방향이 언급되었다.
- 카메라 입력은 노트북 웹캠, 휴대폰 카메라, CCTV 모니터 촬영 등 여러 방식을 고려할 수 있다.
- 기준 프레임을 캡처하고, 그 위에서 주차면을 추가/수정한 뒤 모니터링을 시작하는 흐름이 적합하다.
- 모니터링은 1분 간격처럼 일정 주기로 프레임을 캡처하여 분석하는 구조가 현실적이다.
- 현장 테스트를 위해 노트북/휴대폰 또는 소형 컴퓨터와 카메라를 설치하는 방안이 논의되었다. 전원은 가능할 수 있으나 와이파이는 어려울 수 있어 저장 방식과 네트워크 의존도를 고려해야 한다.
- 동일 프로그램으로 3~4개의 영상에 대해 각각 다른 주차면 설정을 불러와 테스트할 수 있어야 한다.

2-5. 7월 23일 회의 요약

- 교수님은 주차면 점유 인식 프로젝트가 기대 이상으로 완성되어 있다고 평가했다.
- 다만 실제 차량 인식 정확도, 차량 일부만 보이는 경우, 여러 주차면이 겹쳐 보이는 경우, 실제 현장 CCTV 환경에서의 작동 여부는 추가 검증이 필요하다.
- 커넥트현대 현장에서 실제 테스트를 수행하는 것이 가장 좋은 검증 방법으로 제안되었다.
- CCTV 화면을 보여주는 모니터를 카메라로 촬영하고, 영상에서 주차 구역별 점유 여부를 분석하는 방식이 현실적인 검증 방법으로 언급되었다.
- 카메라 입력 방식, 프레임 추출 주기, 주차면 좌표 저장 방식, 차량 인식 및 점유 판정 알고리즘을 구체화해야 한다.

3. 교수님 예시 코드 검토

3-1. 01_yolov8n.py

- yolov8n.pt를 사용해 일반 차량 bbox를 검출하는 기본 예시다.
- car 클래스 중심으로 영상에서 차량 수를 확인하는 데는 간단하고 좋다.
- 하지만 주차면 점유 판단에는 한계가 있다. bbox는 차량의 실제 바닥 영역보다 크게 잡힐 수 있고, 비스듬한 CCTV 각도에서 인접 주차면과 겹쳐 보이는 문제가 생긴다.
- 따라서 01은 기본 YOLO 사용법 확인용 또는 baseline으로만 두는 것이 적합하다.

3-2. 02_yolov8n-seg.py

- yolov8n-seg.pt를 사용해 차량 segmentation mask를 얻고, 차량의 바닥 footprint를 추정한 뒤 주차면 polygon과 겹치는 비율로 점유 여부를 판단한다.
- car, truck, bus, motorcycle을 차량 후보로 보고 있어 실제 주차장 환경에 더 맞다.
- 원본 영상 좌표를 bird-eye-view 좌표로 변환하는 homography 구조가 들어 있어, 비스듬한 CCTV 각도 문제를 줄일 수 있다.
- 주차면을 polygon으로 정의하고 교차 면적 비율이 일정 임계값 이상이면 occupied로 판단하는 방식이므로, 단순 bbox 방식보다 주차 점유율 계산에 적합하다.
- 따라서 앞으로 개발은 02_yolov8n-seg.py의 YOLO segmentation + 투시 변환 + 주차면 polygon 교차 판단 방식을 기준으로 진행하는 것이 좋다.

4. 권장 개발 방향

4-1. 기본 구조

- 분석 기준 모델: yolov8n-seg.pt 또는 같은 계열의 YOLO segmentation 모델
- 입력 방식: 영상 파일, 웹캠, CCTV 모니터 촬영 카메라, 추후 실제 CCTV 스트림
- 설정 방식: 첫 프레임에서 사용자가 주차면을 직접 지정하고 좌표 파일로 저장
- 판단 방식: 차량 segmentation mask → 차량 바닥 영역 추정 → BEV 변환 → 주차면 polygon과 교차 면적 계산
- 결과: 주차면별 occupied / empty / unknown, 전체 점유율, 분석 시각, 로그 저장
- 저장 정책: 분석용 캡처 이미지는 최근 10장만 보관하고, 장기 기록은 CSV/JSON 결과 로그 중심으로 저장

4-2. 프로그램 모드

- 설정 모드
  - 영상 또는 카메라에서 기준 프레임을 캡처한다.
  - 사용자가 주차면마다 4개 점을 클릭해 영역을 지정한다.
  - 주차면 ID를 입력한다. 예: A1, A2, A3
  - 카메라 투시 보정을 위한 기준 ground point 4개도 지정할 수 있게 한다.
  - 설정값을 JSON으로 저장한다.

- 모니터링 모드
  - 저장된 설정 파일을 불러온다.
  - 영상/카메라에서 일정 주기로 프레임 1장을 가져온다.
  - YOLO segmentation으로 차량 후보를 검출한다.
  - 각 차량 footprint와 주차면 polygon의 겹침 비율을 계산한다.
  - 주차면별 상태와 전체 점유율을 화면에 표시한다.
  - 분석 결과를 CSV 또는 JSON 로그로 저장한다.
  - 캡처 이미지는 최근 10장만 유지하고 오래된 이미지는 자동 삭제한다.

4-3. 점유율 계산

- 전체 주차면 수 = 설정 파일에 등록된 slot 개수
- 점유 주차면 수 = occupied 상태인 slot 개수
- 점유율 = 점유 주차면 수 / 전체 주차면 수 * 100
- unknown 상태는 별도 표시하고, 운영 정책에 따라 점유율 계산에서 제외하거나 보수적으로 점유로 처리할 수 있다.
- 초기 개발 단계에서는 unknown을 점유율 계산에서 제외하고 별도 비율로 보여주는 방식이 좋다.

4-4. 안정화 로직

- 한 프레임만 보고 상태를 바꾸지 않는다.
- 최근 N회 분석 결과를 저장하고, 같은 상태가 2~3회 연속 확인되면 최종 상태를 변경한다.
- 움직이는 차량이 특정 주차면을 잠깐 가리면 unknown으로 둔다.
- 검출 confidence가 낮거나 차량 footprint가 주차면 경계에 애매하게 걸치면 unknown 또는 이전 상태 유지로 처리한다.
- 10초, 30초, 1분 간격을 옵션으로 두고, 현장에서는 1분 간격부터 검증하는 것이 적합하다.

5. MVP 개발 순서

1. Ax-RnD-PARKING 프로젝트 구조 정리

- data/: 테스트 영상
- config/: 주차면 좌표 JSON
- outputs/: 최근 10장 캡처 이미지, 분석 결과 로그
- src/: 분석 코드
- app/: 웹앱 또는 GUI 코드

2. 02_yolov8n-seg.py를 설정 파일 기반으로 정리

- 코드 안에 박혀 있는 SOURCE_GROUND_POINTS, DEST_GROUND_POINTS, slot 좌표를 JSON에서 읽도록 변경한다.
- 영상 경로, 모델 경로, 분석 간격, 점유 임계값을 옵션화한다.

3. 주차면 설정 도구 제작

- 첫 프레임을 띄운다.
- 사용자가 마우스로 4점을 클릭해 주차면 polygon을 만든다.
- slot ID를 붙여 저장한다.
- 저장 결과를 분석 코드에서 바로 사용할 수 있게 한다.

4. 점유 분석 루프 제작

- 5분 간격으로 프레임 1장을 추출한다.
- YOLO segmentation을 실행한다.
- 주차면별 occupied / empty / unknown을 계산한다.
- 전체 점유율을 계산한다.

5. 화면 UI 제작

- 좌측: 영상 또는 캡처 프레임
- 우측: 주차면 목록, 상태, 점유율, 마지막 분석 시간
- 설정 모드와 모니터링 모드를 분리한다.
- 개발자/설치자가 쓰기 쉬운 형태를 우선 목표로 한다.

6. 테스트

- 교수님 예시 영상과 추가 촬영 영상 3~4개를 대상으로 테스트한다.
- 각 영상마다 별도 config 파일을 만들어 같은 분석 코드로 돌린다.
- 실제 정답과 비교해 slot 단위 정확도, 오탐, 미탐, unknown 비율을 기록한다.

7. 현장 검증

- 커넥트현대 현장에서 CCTV 모니터를 카메라로 촬영하는 방식으로 테스트한다.
- 가능하면 고정 삼각대, 일정한 촬영 각도, 반사광 최소화가 필요하다.
- 네트워크 없이도 로컬 저장/분석이 되도록 구성한다.
- 저장 공간 관리를 위해 캡처 이미지는 최근 10장만 보관하고 원본 영상은 저장하지 않는다.

6. 주요 리스크와 대응

- 반사광/화질 저하: 카메라 고정, 모니터 밝기 조정, 촬영 각도 조정
- 영상 흔들림: 고정 거치대 사용, 필요 시 영상 안정화 적용
- 비스듬한 CCTV 각도: homography와 BEV 변환 사용
- 인접 주차면 겹침: bbox가 아니라 segmentation mask와 footprint 기반 판단 사용
- 검은색 차량/부분 가림: confidence threshold 조정, temporal smoothing, unknown 상태 도입
- 실시간 성능: 매 프레임 처리 대신 일정 주기 분석
- 현장 네트워크 제약: 로컬 카메라/로컬 저장 우선, 추후 네트워크 연동

7. 지금 진행 방향 제안

현재 목표가 “CCTV 주차장 연습 영상을 보고 주차 점유율을 확인하는 프로그램”이라면, 02_yolov8n-seg.py를 기준으로 가는 것이 맞다.
01_yolov8n.py는 차량 bbox 검출 예시로는 좋지만, 주차면 점유처럼 영역 겹침과 카메라 각도가 중요한 문제에는 부족하다.
02의 핵심인 segmentation mask, 차량 footprint, 주차면 polygon, 교차 면적 비율, BEV 변환 구조를 유지하면서 프로그램화하는 방향이 가장 현실적이다.

처음부터 자동 주차면 인식까지 만들려고 하면 난이도가 커진다.
따라서 1차 목표는 “사용자가 주차면을 직접 지정하고, 프로그램이 그 좌표를 기준으로 점유율을 계산하는 MVP”로 잡는 것이 좋다.
이후 정확도가 충분히 나오면 자동 주차면 후보 추천, VLM 보조 판단, 실제 CCTV 스트림 연결을 순서대로 붙이면 된다.

권장 우선순위는 다음과 같다.

1. 02_yolov8n-seg.py를 config 기반 분석기로 정리한다.
2. 주차면 좌표를 클릭으로 저장하는 설정 도구를 만든다.
3. 영상 파일 기준으로 점유율 계산이 안정적으로 되는지 검증한다.
4. 웹캠/휴대폰 카메라 입력을 붙인다.
5. 현장 CCTV 모니터 촬영 방식으로 테스트한다.
6. 결과 로그와 UI를 정리해 교수님께 보여줄 수 있는 프로토타입으로 만든다.
